# Verification

For a code change inspect Git diff, preserve user edits, run relevant tests and report exact commands/results. For an audit default read-only; reproductions may use temporary isolated files. For a refactor establish behavior baseline, change incrementally, rerun relevant regression tests; don't change acceptance truth. For docs-only changes check affected references/examples; no full code lifecycle required. For new features use meaningful failing tests before implementation where practical, then green and regression. For algorithm optimization freeze metrics, data splits and independent evaluator, use bounded experiments and final holdout validation. For frontend use actual browser interaction and screenshot evidence when available. For backend validate schema, errors, integration, concurrency and migration as relevant.

Acceptance: compare against approved requirements/criteria, run actual tests, present results and remaining risks, request user acceptance when needed. Record accepted scope and Git revision plus test commands in existing acceptance/design document or concise project log. Use Git and CI to protect behavior, contract and evaluator changes; do not freeze entire implementation files. If previously accepted behavior or criteria intentionally change, approve impact and rerun affected checks. An agent's report is not independent enforcement; owner-controlled CI, required reviews and isolated evaluators are necessary for high assurance. No fabricated proof, receipt hashes or self-approval.
