Use Trellis for human-controlled development. Record real user product requirements in the ordered Markdown raw/functional lists (1., 2., 3.; functional numbering restarts per category); skip operation-only commands and AI guesses. Edit in place, strike deleted descriptions and update only the last edit date. No tables or permanent IDs. Use the eight Trellis entry skills and their task-specific workflow rules; load required upstream resources before the related work, including Ponytail before substantive coding. Reuse accessible native/existing plans. Small reversible tasks execute and verify directly. For major changes confirm design, interfaces, skeleton and consequential plan/acceptance criteria in order before implementation. Protect accepted behavior and independent tests with Git, actual regression checks and explicit approval for material changes. Do not weaken evaluation or claim unrun tests passed. Keep documentation concise and consistent with code.
